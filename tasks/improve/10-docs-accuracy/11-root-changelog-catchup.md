## Context

are published at **0.6.0** (see any `packages/*/package.json`). Users and AI agents
reading the root changelog see a stale history.

## Constraints

- Do not invent changes: derive entries from per-package changelogs and git history.

## Steps

2. If per-package changelogs are missing entries, run `git log --oneline -n 100` and inspect
   tags/merge commits for the relevant releases.
3. Add `## [0.6.0]`, `## [0.5.0]`, `## [0.4.0]` sections to the root `CHANGELOG.md`,
   newest first, above the existing `[0.3.0]` section. Use the same section style
   (`### Bug Fixes`, `### Improvements`, etc.).
4. Keep entries concise — one line per change, grouped by package where useful.
